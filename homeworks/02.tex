\begin{task}{Proof of work}
  Task template file: \texttt{pow\_template.py}

  \textit{Background.}
  The core idea behind a proof of work (PoW) is to prove that you have expended some amount of computational effort.
  In essence, it is a puzzle that is computationally costly to solve, but the solution of which is easy to verify (similarly to the desired asymmetry in public-key cryptography).

  In this task, you must implement a simple variant of the \href{https://en.wikipedia.org/wiki/Hashcash}{\textit{Hashcash}} proof-of-work system, which is used for example in Bitcoin mining.
  You may (but need not) read more about Bitcoin's proof of work \href{https://en.bitcoin.it/wiki/Proof_of_work}{\textit{here}}.

  \textit{Context.}
  You will mine a tiny blockchain of two blocks, each of which is a simplified version of a Bitcoin block.
  Each block commits to a list of entries through a Merkle tree, and to the previous block through its hash.
  A block is only valid if its hash starts with at least 25 zero bits (the challenge \enquote{difficulty}).

  \newpage

  The header of a block is the 76-byte string
  \begin{Verbatim}
prev_hash || merkle_root || leaf_count || nonce
  \end{Verbatim}
  where
  \begin{itemize}
    \item \texttt{prev\_hash} (32 bytes) is the hash of the previous block, or 32 zero bytes for the first block;
    \item \texttt{merkle\_root} (32 bytes) is the Merkle root of the block's entries;
    \item \texttt{leaf\_count} (4 bytes, big-endian) is the number of entries in the block;
    \item \texttt{nonce} (8 bytes, big-endian) is the value you search for.
  \end{itemize}
  The hash of a block is \texttt{SHA256(SHA256(header))}.

  The blocks to mine are
  \begin{Verbatim}
Block 1: ["Stone", "Coal Ore", "Iron Ore", "Diamond Ore", username]
Block 2: ["Obsidian", "Ancient Debris", username]
  \end{Verbatim}
  where \texttt{username} is your student username, e.g. \texttt{takraa}.
  The \texttt{prev\_hash} of block 2 is the hash of block 1.

  \textit{Instructions.} Implement the function
  \begin{Verbatim}
merkle_root(entries: list[str]) -> bytes
  \end{Verbatim}
  that computes the Merkle root of the entries with the \enquote{duplicate last leaf} approach:
  \begin{itemize}
    \item a leaf is \texttt{SHA256(s)}, where \texttt{s} is the UTF-8 encoded entry;
    \item a parent is \texttt{SHA256(left||right)};
    \item if a level has an odd number of nodes, the last node is paired with itself.
  \end{itemize}

  Implement the function
  \begin{Verbatim}
l0_bits(bs: bytes) -> int
  \end{Verbatim}
  that counts the number of leading zero bits in the byte string and returns it.
  Since this is part of the code logic, you may not ask an AI to generate it for you.

  \newpage

  Implement the function
  \begin{Verbatim}
bruteforce(seed: bytes, difficulty: int) -> tuple[int, bytes]
  \end{Verbatim}
  that iteratively generates 8-byte nonces until \texttt{SHA256(SHA256(seed||nonce))} starts with at least \texttt{difficulty} zero bits, and returns the nonce and that hash value.
  Use big-endian encoding for the nonce.
  That is, you try the nonces:
  \begin{enumerate}
    \item \texttt{0x0000000000000000}
    \item \texttt{0x0000000000000001}
    \item \texttt{0x0000000000000002}
    \item \dots
  \end{enumerate}
  To mine a block, the seed is the header without the nonce:
  \begin{Verbatim}
prev_hash || merkle_root || leaf_count
  \end{Verbatim}

  The functions must also handle other difficulty settings and possible edge cases.

  For example, for the username \texttt{takraa}:
  \begin{itemize}
    \item block 1 has the Merkle root
    \begin{Verbatim}
42ae22ace5127cb6ed01d00220a57236c5f1b431ecc11a7841789c0ebe68b085
    \end{Verbatim}
    the smallest valid nonce is $18027076$, and the block hash is
    \begin{Verbatim}
0000001c3fbcadaef7347c72a83308201dd57b005ff2744aa626a43b04ed33a2
    \end{Verbatim}
    \item block 2 has the Merkle root
    \begin{Verbatim}
9b0e337b97af29fda0d730dc56920ba245727232c95064e3c832062614ae3938
    \end{Verbatim}
    the smallest valid nonce is $5872423$, and the block hash is
    \begin{Verbatim}
000000063f92d1396d0ad535fc852886afa3b85ab256c9f0bc5edc34bd0a0b40
    \end{Verbatim}
  \end{itemize}
  Mining both blocks took under a minute on my laptop.

  You may edit \texttt{main()}, but the printed output must be for the given blocks and difficulty, and keep the template's format.
  Include the printed output in your report!

  Answer the following in your report:
  \begin{itemize}
    \item Why does the header contain \texttt{leaf\_count}?
    What could go wrong without it?
    \item Suppose someone replaces \enquote{Iron Ore} in block 1 with another entry.
    What must they recompute to obtain a valid chain again, and why?
  \end{itemize}
\end{task}
